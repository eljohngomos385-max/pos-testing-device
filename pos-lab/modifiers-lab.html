Modifiers & add-ons, step by step

A Gong cha store setting up its Matcha Latte. First the two words, then one job per scenario: every tap, and the POS screen you get at the end. At the bottom: the full spec and every decision, for whoever builds it.
Building it? Start with pos-vault/plans/modifiers-build.md (10-22). Where it differs from this page, it wins: no usuals (nothing starts picked; ignore the filled 50% and "Add fills the usuals"), hiding a choice on one item (its own page), Unavailable behind a role switch, a sales report by modifier.
Add-ons are for later, with QR ordering (owner, 10-22): the POS gets no add-on step for now. Scenarios 3 and 4, and the Add-ons screen in 5, show how they'll work then.

For whoever builds this

The full spec

Everything the scenarios show, as rules. Read this first; the phones above are the same thing in pictures. Owner decisions are marked settled; don't reopen them.

What there is

  • In one breath (owner, 10-22): Variant = which item it is (a size, a colour): searchable, a tile, its own stock. Modifier = preset choices the owner makes, switched on per item; never searchable, never a tile. Add-on = a list of items or variants offered at the end; tapping one acts exactly like its tile, opening its own pages if it has any.
  • Modifier = a name, Customer picks (One / Up to 2 / Up to 3 / Any), its choices, and Asked on (which items ask it).
  • Choice = a name and a price (₱0 allowed). No picture, no stock. Optional usual: One has at most one, Any can have several. Status: Available / Unavailable.
  • Order is per drink: dragged with ≡ on the drink's Modifiers page. A modifier selected on a drink goes last.
  • Add-on = a real item (price, picture, stock, sales line).
  • Add-on set = a name only the owner sees, its items, and Used on.
  • A drink's add-ons = the sets it selects + single items it chooses from Items. Sets are only made on the Add-ons tab.
  • Size is not a modifier. Sizes are the item's variants, each with its full price.
  • Asked on (from the modifier) and the drink's Modifiers row are one link, seen from two sides. Same for a set's Used on and the sets the drink selects.

Setting up (Items)

  • Modifiers tab: list (name, choices, "N items"), + for new. No order here.
  • Modifier page: Name · Customer picks (tap = sheet with the 4 ways, each explained) · Choices (Add choice opens a page like Add variant: Name, Price; each row › opens Edit choice: Name, Price, Status Available / Unavailable, Remove choice) · Asked on · Delete modifier at the bottom (saved ones only).
  • Usual: a circle on each choice, drawn like the POS (round for One, square for Any). Filled = starts picked. Tap again = no usual.
  • Asked on / Used on / Add from Items / Choose from Items: one Items select list. Search, Filters sheet from the search bar, Select all for the filtered list, Done bottom right. Rows: picture, name, "Category · Stock N", price.
  • Add-ons tab: the sets. Set page: Name · Items · Used on · Delete set.
  • Drink page: Modifiers row = select list of modifiers, selected on top with ≡ (this drink's order). Add-ons row = Sets (select list, ≡) + Items (Choose from Items; deselect there to remove; items a selected set already offers are greyed). No sets yet? Only Items shows. Nothing is created here.

Selling (POS)

  • Tap a tile with questions: one question per screen. Order: size (if it has variants), the modifiers in the drink's order, add-ons last (once QR ordering has them). Dots show where you are; the top line shows the answers so far.
  • Pick one: tapping a choice picks it and moves on (≈220 ms).
  • Up to N / Any: taps toggle; Next top right. With Up to N, once N are picked the rest grey out.
  • Add (bottom pill, every screen, with the running price): every question left takes its usual, the add-ons are skipped, the line goes in. A normal order is tile + Add.
  • Pick one with no usual: the pill reads "Pick a size" (dimmed) and waits until it's answered.
  • Back goes to the previous question; ✕ on the first one cancels.
  • Add-ons screen (later, QR ordering first): "Optional", one list (each selected set's items in the drink's set order, then the drink's own items; each item once), − n + per item.
  • Unavailable: the choice's Status in setup, or hold it on the POS › Unavailable. Greyed on every drink until set back to Available.
  • Cart line: "Drink Size" at the size's price; under it one line per answer, "Question: choice", with its price on the right if it has one. Add-ons are their own lines.
  • Tap a cart line: rows for each answer (tap = that question screen), Note, Quantity, Remove from order (not red); Save.
  • Receipt and kitchen slip: the cart lines, the note last. The slip prints every answer, even ₱0 usuals: the kitchen needs them.

Settled, and why

  • Choices have no picture or stock: setup stays typing, like Grab and Foodpanda. Need it counted? Make it an item and offer it as an add-on.
  • One question per screen: picked over one sheet and scroll-and-fill (kept below for comparing).
  • Add fills the usuals, for rush hour. The cost: Add skips the add-ons screen, so a rushed order gets no upsell.
  • Size is variants: each size already has its own price, stock and sales line. A Size modifier would copy that.
  • The usual is set in setup with the circle. On the POS, holding a choice only means Unavailable: one gesture, one meaning.
  • A choice is Unavailable, not Sold out (owner, 10-22): it can be off for any reason, and it stays in the list. An item can be made inactive; a choice needs the same switch. Gone for good = Remove choice (like Remove variant).
  • Sets are kept: change Snacks once and every drink using it changes (8 drinks × 3 snacks = 24 taps otherwise). Kept because the owner likes sets.
  • Sets are made only on the Add-ons tab. On the drink you select sets or choose single items from Items; a set is never created there (owner, 10-22). Several sets per drink. The set name never shows on the POS.
  • Question order is per drink, not one store list (owner, 10-22: a donut and a drink can't share one order).
  • Receipt lines say "Question: choice" so "Less" or "50%" never stands alone, and the drink shows its own price so the sums add up on paper.
  • Unavailable at shift close: stays off until someone sets it back to Available, like a Hidden item (owner, 10-22). Picked over "back on by itself each morning".
  • Kitchen slip: an add-on prints as its own line, not inside the drink (owner, 10-22: "add-on should be its own thing").
  • The Modifiers tab stays for every kind of store, retail too (owner, 10-22). Colours and sizes are variants (Latex Paint White 4 L, Ivory 4 L): real items with stock. A modifier is a question with no stock (Gift wrap).
  • Unavailable is per modifier (owner, 10-22): one modifier shared by many drinks = one switch, off on all of them. Pearls in two separate modifiers = two switches. Copying a choice into two modifiers is the shop's own choice; Grab works the same.
  • Add-ons stay separate from modifiers (owner, 10-22): a modifier is a question about the item; an add-on is an upsell, another item. Folding them together would lose the add-on's stock and sales line.
  • Choice names shouldn't clash with item names (the topping is Grass jelly, not "Pudding", next to the Egg Pudding add-on).

Parked, for later

  • Meals and combos (McChicken Meal): for now a "Drink" modifier with no usual, so the cashier must pick. "Pick 2 sides" = up to 2, not exactly 2 (owner, 10-22); parked with meals.
  • Price by size (Pearls +₱15 on Medium, +₱20 on Large).
  • First topping free, or N free.
  • Questions inside questions (picked Hot › ask "Milk?").
  • Half-and-half (pizza).
  • A choice using ingredient stock ("Pearls uses 30 g").
  • Photos on variants: the owner will decide later.
  • Double pearls as a counter: for now an "Extra pearls" choice.
  • Unavailable is per store: every POS in that store sees it, other stores don't.

Add-ons: decided, build with QR ordering

  • When: add-ons are customer-facing, so they wait for the guest's order screen: QR ordering first, then a kiosk or online ordering (owner, 10-22: "add-ons is a customer facing thing, so probably it should wait"). The POS has no add-on step for now; the cashier taps the item on Sell.
  • What can be an add-on: any item. On the drink (or in a set) you pick a whole item = any size, or open it and pick exact sizes (Fries Large only). An item is a folder of variants.
  • Tapping + runs that item's own Sell steps: the size if none is fixed, then its own questions, with its usuals already picked. Nothing to ask (Egg Pudding) = one tap. Then back to "Anything else?".
  • One level only: an add-on's own add-ons are never offered, so nothing loops.
  • Its own line in the cart, at its normal price and stock, on the receipt and the kitchen slip. Refunded like any line.
  • Removing the drink leaves the add-on in the cart (owner, 10-22): it's an upsell the customer said yes to, not part of the drink. No link from the add-on line to the drink in the data.
  • Same rules as its Sell tile: Unavailable or inactive = not offered; out of stock asks "Sell anyway?".

Add-ons: how we got there (10-22)

  • The problem: Fries has sizes, a Coke asks "Ice?". How can an item with variants or questions be an add-on?
  • Only plain items: rejected. The burger place couldn't offer Large Fries or a Coke.
  • Fixed rows with the usual answer (what Grab, Loyverse and Square do: a priced choice, no questions): rejected. It breaks on a question with no usual (Coke, "Ice?").
  • Add-ons inside modifiers (a choice that is an item): rejected by the owner. A question about the drink and an upsell are different things.
  • Picked: run the item's own Sell steps, like McDonald's and Jollibee kiosks, Toast and Uber Eats. The owner's words: "it's just an upsell, just another way of selling".
  • Research: Uber Eats nests up to 6 levels and Toast advises 2 for delivery apps; we keep 1. Square's kiosk only upsells items whose questions all have usuals. Loyverse has no stock on choices and no upsell.
  • An add-on with its own questions just opens them (owner, 10-22): "it's like a fail safe". Picking it as an add-on must never lose its options.
  • Still open: typing many choices in fewer trips, without ready-made lists (owner said no). One page for all of them, or a bulk change. See question 2 at the top.

How this lab file works

  • Standalone: pos-lab/modifiers-lab.html. Nothing here touches the pos-lab app.
  • Q drives every POS question screen (draw, rows, pill). v:1 = the size (variants), one:1 = Pick one, add:1 = add-ons, u = the usuals.
  • .ph[data-q] = a static POS screen. data-ring = a choice index, next or add; data-out / data-hold = Unavailable; data-drink / data-only = another drink with fewer add-ons.
  • ITEMS drives the select lists. .ph[data-pick] modes: all, sheet, cat (Asked on), snacks (Add from Items), used (Used on), own (Choose from Items on the drink).
  • #B is the playable sale; #A and the scroll-and-fill phones are the ways not picked.
