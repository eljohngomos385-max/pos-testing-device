Blind test: payment types

Three testers used the screen only, without the code: Settings, Checkout, and Split / refunds. Nothing let a sale skip a required box. Green = fixed or checked, grey = left as is. Tap a picture to open it full size.

1. Checkout › Card (iPad)

Tapped the button with the box empty, then filled it in and finished. The “Enter the last 4 digits first” message was still up on Sale complete.

Fixed: the message goes away on Sale complete.

2. Settings › Payment types

Added a 9th type. It’s added switched off, and the message saying why was cut off on the phone.

Fixed: the message wraps onto two lines.

3. Settings › Payment types › Add payment type

Tapped Save with the name empty (or only spaces). Nothing happened and there was no message.

Fixed: Save is greyed until there’s a name.

4. Checkout › Split › QR (approval code required)

Added a QR part, tapped Back on its approval code box. Complete sale asked for the Cash change first, and only after that went back to the code box.

Fixed: Complete sale asks for the missing code first, then the Cash change.

5. Checkout › Card

“Last 4 digits” takes anything: “12” or “abc” finishes the sale and prints on the receipt.

Leave: you said it’s fine.

6. Settings › Payment types

A long name was cut at 24 letters with no sign it was cut.

Fixed: a long name ends in … so you can see it was cut (24 letters still fits the receipt).

7. Checkout › Card

Typed 1234, tapped Back, picked Card again: the box is empty again.

Leave: you said it’s fine.

8. Checkout › Card

Typed only spaces: the “(required)” hint disappeared, so the box looked empty but the sale couldn’t finish.

Fixed: spaces alone don’t go in the box, so “(required)” stays.

9. Settings › Payment types › Maya

In plain words: on Maya’s page you type “GCash” as the new name. It says “GCash is taken” (right, GCash exists). Then you delete the name and leave. Maya keeps its name (right), but the “GCash is taken” message is still on screen for a second.

Fixed: clearing the name now clears the old message right away.

10. Checkout › Split › GCash

GCash was ₱65. You open it again and delete the number: ₱65 comes back in grey, and Done keeps GCash at ₱65. If you want GCash out of the split: open it, type 0, tap Done. GCash disappears from the list.

Leave: an empty box means “keep what it was”; 0 means “take it off”.

11. Checkout › Split › Cash

The sale is ₱315. Cash is the only part, ₱200. Big number ₱315 = what Cash could cover (nothing else is paying yet). Small box ₱200 = what Cash is paying now.

Leave: big = what this part can cover, box = this part. Say if you want the big number to be the part instead.

12. Orders › Refund

The refund confirm says the amount but not how it goes back (Cash or GCash) on a split sale.

Leave: you said it’s fine.

13. Checkout › Split

You asked: can a split finish if you type 0 in every part? No. A part set to 0 comes off, and Complete sale stays greyed until the parts add up to the total. Forcing it made no order.

Checked: can’t be done.

Also noted, no picture

  • Must fill in stays on while Ask for is Nothing (the row is hidden). It doesn’t block anything, because nothing is asked.
  • Picking an Ask for option doesn’t go back by itself; the tick shows and you tap Back.
  • Cash, GCash, QR, Other, Account and Split can’t be renamed. That’s by design.
  • A renamed type: old sales keep the name they were sold with (Past sales keep the name). By design.
  • The greyed Complete sale still answers a tap with “Enter the … first”. By design.
  • The tester’s browser crashed once and it couldn’t make it happen again. No error from the app.
  • Not tested: Void, Cash in / out, deleting a type that has sales.

Worked

  • The required box can’t be skipped: empty, spaces, Enter, 10 fast taps, Back and pick again, the picture step, iPad.
  • Fast taps on a good sale made one order, not several.
  • An optional box can be left empty. What’s typed shows on the receipt, trimmed.
  • Add, hide, turn all off (only Cash stays), rename, duplicate names blocked (any case), delete and add back.
  • Picture: add, shown first at checkout, Done → box → Complete sale, remove.
  • Split: amounts add up, each part prints on the receipt, each GCash part shows its own picture, Back on a picture takes the part off.
  • Refunds: a renamed type refunds fine, a split refund keeps its payment lines, Void is hidden on a refunded sale.
  • No errors in the app in any run.
